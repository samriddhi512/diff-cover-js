Diff coverage tools for JavaScript compared

Several tools report test coverage only on the lines a change touches. This page compares the ones JavaScript and TypeScript projects usually pick: diff-cover-js, the diff-cover npm package, @connectis/diff-test-coverage, coverage-diff, and the original Python diff-cover.

This page is written by the author of diff-cover-js. Details for the other tools come from their own READMEs, checked on 20 November 2026; "not documented" means the README doesn't mention it, not that the feature is missing. Corrections are welcome in GitHub issues.

Short answer

  • Jest, Vitest, nyc or c8 with lcov, and you want branch coverage on changed lines plus HTML, JSON and Markdown reports: diff-cover-js.
  • You need Cobertura, Clover or JaCoCo reports, or lint checks on changed lines (diff-quality), in Node: the diff-cover npm package.
  • You need separate line, branch and function thresholds, or Mercurial: @connectis/diff-test-coverage.
  • You want to compare whole-file coverage between the base and head branches, not individual lines: coverage-diff.
  • Python is already in your CI, or you use many report formats and languages: Python diff-cover, the original tool.

diff-cover-js

A Node.js tool built for the lcov reports the JavaScript ecosystem already produces. It reports line and branch coverage for the lines a branch adds, skips test files and type declarations by default, and writes Markdown for pull requests and JSON for bots. Line numbers always refer to the file as it is on disk, even when committed, staged and unstaged changes touch the same file. It reads lcov only; Cobertura XML isn't planned.

diff-cover (npm)

A TypeScript port of Python diff-cover, published on npm as diff-cover. It's a different project from diff-cover-js, despite the similar name. Its strengths are the range of input formats, Vite/Vitest config detection, and a diff-quality command for lint results on changed lines.

npm · GitHub

@connectis/diff-test-coverage

A Node.js CLI that reads a diff from standard input, so it works with git, Mercurial or anything that writes a unified diff. It supports many report formats and enforces line, branch and function coverage thresholds on the diff separately. It writes console output only.

git diff origin/main...HEAD | npx @connectis/diff-test-coverage -c coverage/lcov.info -t lcov --

npm · GitHub

coverage-diff

A different kind of tool: it compares two Istanbul coverage-summary.json files (base and head) and reports how coverage percentages changed per file. It works at the file level, so it can catch coverage regressions but can't tell you which changed lines are untested.

npm

Python diff-cover

The original tool, started at edX in 2013 and still the most complete: many report formats, diff-quality for linters, and HTML reports with code snippets. It parses lcov, so it works for JavaScript projects too, but CI needs Python (for example pipx install diff-cover). diff-cover-js follows its approach and flag names; the README lists the differences.
