Jest diff coverage: test coverage on changed lines only

Jest measures coverage per file and per project. To see how well a pull request's new lines are tested, feed Jest's lcov report to diff-cover-js, which compares it with your git diff.

Why Jest's own threshold isn't enough

Jest's coverageThreshold checks totals for the whole project, or for whole files and folders. On a codebase with old, untested code, that leaves two bad options: a low threshold that new code easily passes, or a high one that fails on lines nobody changed.

Options like --changedSince choose which tests run. They don't tell you whether the lines you just wrote are executed by those tests. diff-cover-js answers exactly that: of the lines added since origin/main, how many did Jest run?

1. Install

npm install --save-dev diff-cover-js

2. Make Jest write an lcov report

Add lcov to Jest's coverage reporters. Keep text if you still want the usual table.

// jest.config.js
module.exports = {
  collectCoverage: true,
  coverageDirectory: 'coverage',
  coverageReporters: ['lcov', 'text'],
};

Or pass it on the command line without changing the config:

npx jest --coverage --coverageReporters=lcov

Either way Jest writes coverage/lcov.info.

3. Check coverage on the changed lines

npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main --fail-under 80

diff-cover-js finds the merge base with origin/main, collects the lines your branch adds, and reports which of them Jest executed. With --fail-under 80 it exits with code 1 when fewer than 80% of the changed lines are covered.

Add it to package.json so everyone runs the same check:

{
  "scripts": {
    "test:coverage": "jest --coverage --coverageReporters=lcov",
    "coverage:diff": "diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main --fail-under 80"
  }
}

Check before you push

By default diff-cover-js counts committed, staged and unstaged changes, so you can run it on your working copy before opening a pull request:

git fetch origin main
npm run test:coverage && npm run coverage:diff

Pass --ignore-staged --ignore-unstaged to count only committed changes, or --include-untracked to count new files you haven't added yet.

Branch coverage on changed lines

Jest writes branch data (BRDA records) to lcov by default. diff-cover-js uses it to report branch coverage for the changed lines as a separate figure, and lists the lines where a branch was never taken, such as an if without a test for its else. --fail-under applies to line coverage only.

Jest multi-project and sharded runs

With Jest projects or --shard, the same source file can appear in several lcov blocks, or you may concatenate several lcov files. diff-cover-js merges blocks for the same file by adding their hit counts, as the lcov tool does, so a line covered in any project counts as covered.

cat coverage/shard-*/lcov.info > coverage/lcov.info
npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main

Test files are excluded by default

Changes to *.test.*, *.spec.*, __tests__/, __mocks__/ and *.d.ts don't count. Add more patterns with --exclude 'src/generated/**', or turn the defaults off with --no-default-excludes.

Reports for pull requests

npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main \
  --format html:reports/diff-cover.html,json:reports/diff-cover.json,markdown:reports/diff-cover.md

The Markdown report is ready to paste into a PR comment or a CI job summary. See the GitHub Actions guide for a complete workflow.
