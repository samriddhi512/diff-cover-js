Enforce coverage on changed lines in GitHub Actions

This workflow fails a pull request when the lines it changes aren't covered by tests, and writes a coverage report to the job summary. It runs entirely in your own CI with diff-cover-js: no coverage upload, no third-party service, no token.

The workflow

Save this as .github/workflows/diff-coverage.yml. It assumes Jest; for Vitest, swap the test command (see below).

name: Diff coverage

on:
  pull_request:

jobs:
  diff-coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0          # full history, needed to find the merge base

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - run: npm ci

      - name: Run tests with coverage
        run: npx jest --coverage --coverageReporters=lcov

      - name: Check coverage on changed lines
        run: >
          npx diff-cover-js
          --lcov coverage/lcov.info
          --compare-branch origin/${{ github.base_ref }}
          --fail-under 80
          --format markdown:diff-cover.md

      - name: Add report to job summary
        if: always() && hashFiles('diff-cover.md') != ''
        run: cat diff-cover.md >> "$GITHUB_STEP_SUMMARY"

If diff-cover-js isn't in your devDependencies, npx downloads it on each run. Adding it with npm install --save-dev diff-cover-js pins the version in your lockfile.

How it works

  • fetch-depth: 0 fetches the full history. diff-cover-js runs git merge-base between the base branch and HEAD, which fails on the default shallow clone.
  • origin/${{ github.base_ref }} is the pull request's target branch, so the same file works for PRs into main, develop or a release branch.
  • --fail-under 80 makes the step exit with code 1 when less than 80% of the changed lines are covered, which fails the check on the pull request.
  • --format markdown:diff-cover.md writes the report before the threshold check, so the summary step can show it even when the check fails. if: always() runs that step after a failure.

To block merging, make the diff-coverage job a required status check in the branch protection rules (or ruleset) for your base branch.

Using Vitest

Install @vitest/coverage-v8 (or @vitest/coverage-istanbul) and change the test step:

      - name: Run tests with coverage
        run: npx vitest run --coverage --coverage.reporter=lcov

More detail in the Vitest guide.

Post the report as a PR comment

The job summary needs no permissions. To also comment on the pull request, give the job write access and use the GitHub CLI that's preinstalled on GitHub-hosted runners:

jobs:
  diff-coverage:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      # ... same steps as above ...

      - name: Comment on the pull request
        if: always() && hashFiles('diff-cover.md') != ''
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh pr comment ${{ github.event.pull_request.number }} --body-file diff-cover.md

This adds a new comment on every push. Pull requests from forks get a read-only token, so the comment step fails there; the job summary still works.

Keep the HTML and JSON reports

      - name: Check coverage on changed lines
        run: >
          npx diff-cover-js
          --lcov coverage/lcov.info
          --compare-branch origin/${{ github.base_ref }}
          --fail-under 80
          --format markdown:diff-cover.md,html:reports/diff-cover.html,json:reports/diff-cover.json

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: diff-coverage-report
          path: reports/

Troubleshooting

"No merge base found between … and HEAD"

The checkout is shallow, so the common ancestor of your branch and the base branch wasn't fetched. Set fetch-depth: 0 on actions/checkout, or run git fetch --unshallow before diff-cover-js.

Coverage looks too high, or a changed file is missing

Changed files with no entry in lcov.info are left out of the total. Check that your test runner's coverage includes the file (for example Jest's collectCoverageFrom or Vitest's coverage.include) and that its SF: path matches the path in the repository; in a monorepo, see monorepos. To count such files as uncovered instead, add --strict. It applies to every changed file, including JSON and config files, so pair it with --exclude '**/*.json' '**/*.config.*'.

Generated files are counted

By default staged and unstaged changes count too. If a CI step rewrites tracked files before diff-cover-js runs (code generation, version stamping), exclude them with --exclude 'src/generated/**' or pass --ignore-staged --ignore-unstaged to count committed changes only.
