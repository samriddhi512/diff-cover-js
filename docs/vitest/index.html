Vitest diff coverage: coverage on changed lines only

Vitest's coverage thresholds apply to whole files or the whole project. To check only the lines a pull request adds (patch coverage), have Vitest write an lcov report and run diff-cover-js against your base branch.

1. Install a coverage provider and diff-cover-js

Vitest needs a coverage provider. Either one works, since both can write lcov:

# v8 (default provider, faster)
npm install --save-dev @vitest/coverage-v8 diff-cover-js

# or Istanbul
npm install --save-dev @vitest/coverage-istanbul diff-cover-js

Install the provider version that matches your vitest version.

2. Add the lcov reporter

// vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',            // or 'istanbul'
      reporter: ['lcov', 'text'],
    },
  },
});

Or set it from the command line:

npx vitest run --coverage --coverage.reporter=lcov

Vitest writes coverage/lcov.info. If you set coverage.reportsDirectory, the file is in that folder instead.

3. Check the changed lines

npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main --fail-under 80

This exits with code 1 when fewer than 80% of the lines added since the merge base with origin/main are covered. The console report lists the uncovered line numbers per file.

Package scripts

{
  "scripts": {
    "test:coverage": "vitest run --coverage",
    "coverage:diff": "diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main --fail-under 80"
  }
}

Or use a config file

Put the settings in .diff-cover-js.json at the project root and run npx diff-cover-js with no flags:

{
  "lcov": "coverage/lcov.info",
  "compareBranch": "origin/main",
  "failUnder": 80,
  "format": "markdown:reports/diff-cover.md"
}

Branch coverage

Both Vitest providers include branch data in the lcov report. diff-cover-js reports branch coverage on the changed lines as a separate figure and lists the lines with untaken branches. --fail-under applies to line coverage only.

Monorepos and Vitest projects

diff-cover-js matches the SF: paths in lcov to the paths in the git diff, which are relative to the repository root. Absolute SF: paths are converted to repository-relative ones; relative paths are read as already relative to the repository root.

That matters in a monorepo: when you run Vitest inside packages/web, it writes SF:src/foo.ts, but the diff calls the file packages/web/src/foo.ts. The paths don't match, and changed files with no matching coverage data are left out of the total, so the result can look better than it is. Two setups that work:

Run Vitest once from the repository root

List your packages under test.projects in a root config. Vitest then writes one lcov report with paths relative to the root:

// vitest.config.ts at the repository root
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    projects: ['packages/*'],
    coverage: {
      provider: 'v8',
      reporter: ['lcov', 'text'],
    },
  },
});
npx vitest run --coverage
npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main

Or prefix each package's paths, then combine

If each package runs its own tests, add the package folder to its relative SF: paths while concatenating the reports. Absolute paths are left as they are:

mkdir -p coverage && : > coverage/lcov.info
for d in packages/*/; do
  sed "s#^SF:\([^/]\)#SF:${d}\1#" "${d}coverage/lcov.info" >> coverage/lcov.info
done
npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main

Blocks for the same file are merged by adding hit counts, so a file covered by several packages' tests is handled correctly.

Catch missing files with --strict

--strict counts every changed file that isn't in the lcov report as uncovered, so a path mismatch shows up as 0% instead of disappearing. It applies to all changed files, including package.json, lockfiles and config files, so exclude those:

npx diff-cover-js --lcov coverage/lcov.info --compare-branch origin/main --strict \
  --exclude '**/*.json' '**/*.config.*'
